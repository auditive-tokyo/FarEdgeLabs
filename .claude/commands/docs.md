---
description: 実装で触ったディレクトリの CLAUDE.md を、その変更に合わせて更新する
---

直前の実装で何を触ったかを `git status` と `git diff`（未コミットなら working tree、
コミット済みなら `git diff origin/main..HEAD`）で確認し、**触ったディレクトリの
`CLAUDE.md`** を更新してください。無ければ作る。

## どこに書くか

| 何を | どこに |
|---|---|
| 全体に効く制約・全ディレクトリに関わる約束 | ルートの `CLAUDE.md` |
| **そのディレクトリだけの約束** | `<dir>/CLAUDE.md` |
| いつ何を決め、**何を却下したか** | `DECISIONS.md` |
| まだ手が要ること | `TODO.md` |

ネストした `CLAUDE.md` は**そのディレクトリのファイルを読んだときだけ**自動で載る。
だから「詳細はあちらを見よ」というポインタは書かなくてよい — 勝手に届く。

**1ファイル 200行未満を目安に。** 長いほどコンテキストを食い、遵守率が下がる。
ルートが膨らんできたら、それはディレクトリ側へ降ろす合図。

## 何を書くか

**なぜそうなっているか**と、**素直に書くと何が壊れるか**。この2つだけ。

書かない:

- **何をしているか** — コードが言う
- **コードから導けること** — ディレクトリ構成、依存の一覧、エクスポートの一覧。
  これらは書いた瞬間から腐り始め、しかも腐っても誰も気づかない
- **一度きりの作業ログ** — それは `git log`

日本語で書く。既存の英語は、そのコードを触るついでに直す（翻訳だけのコミットは作らない）。
識別子・型名・外部 API のフィールド名・機械が読むディレクティブは英語のまま。

## 判断が要る場合

- **アーキテクチャの選択をした**（採用と却下がある） → `DECISIONS.md` に ADR を足す。
  却下した案とその理由が本体で、そこが後から復元できない部分
- **やり残した / 意図的に見送った** → `TODO.md` に、決めた内容と理由つきで
- **恒久的な制約が変わった** → ルートの `CLAUDE.md`

## 最後に

更新した内容を、**実装の差分と突き合わせて**齟齬が無いか確認してください。
資料が実態とズレる典型は「実装を変えたが資料は前の説明のまま」で、それは
書き足すより見つけにくい。
