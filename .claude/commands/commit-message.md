`git status` と差分（ステージ済みがあれば `git diff --staged`、無ければ working tree）を
読んで、**一文のコミットメッセージを1つ**提案してください。

**コミットはしない。** `git add` / `git commit` / `git push` は人がやる
（ルートの `CLAUDE.md`「作業の進め方」）。出すのは本文だけ。

## 書き方

日本語。**何をしたか**を終止形で一文。prefix も conventional commits も使わない。

```
localeHref のスラッシュ除去を正規表現から分割へ替える
単位の正規表現に両端アンカーを付けて二次の戻りを断つ
デプロイされない道具を Sonar の解析対象から外し、死んだ cdk の除外を消す
```

**理由が件名から読み取れないときだけ**、括弧で短く足す。

```
除外を .sonarcloud.properties へ移す（自動解析は sonar-project.properties を読まない）
Sonar で Accepted にした 8 件の理由を残す（API に理由欄が無いため）
```

## 避けること

- **ファイル名の羅列** — 差分を見れば分かる。何が変わったかではなく**何をしたか**を書く
- **「修正」「更新」だけ** — 何をどうしたのか分からない
- 2文以上。収まらないなら、たぶんコミットを分けたほうがよい。**そう思ったらそう言うこと**
