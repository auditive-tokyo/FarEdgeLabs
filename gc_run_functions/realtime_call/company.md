### コーポレートサイト・社内基盤の開発（2026 年 7 月 〜 2026 年 8 月）

**プロジェクト概要**
自社コーポレートサイトおよび周辺クラウド基盤の設計・実装・運用。
フロントエンド、サーバーレス関数、インフラ、CI/CD、セキュリティ設計までを単独で担当。

**担当業務**

- Next.js 16 (App Router) / React 19 / TypeScript / Tailwind CSS v4 によるフロントエンド設計・実装
- Route Group による多言語構成（ja / en）と辞書ファイルベースの i18n 基盤の構築
- **WebGL2 / GLSL によるハーフトーン動画レンダラーの実装**
  - 動画をデコードしてフレーム列を事前生成する処理の実装
  - フラグメントシェーダーによるセル単位サンプリング、Rec.709 輝度演算、ガンマ補正、アンチエイリアス、透視投影
- Terraform による GCP インフラの全面 IaC 化（HCL 約 43KB）
- **Workload Identity Federation によるキーレス CI 認証の設計・実装**
- Python (Cloud Run Functions) による問い合わせフォーム API・稼働統計集計バッチの実装
- GitHub Actions による Terraform plan / apply の分離、静的解析、ビルド・デプロイ自動化
- SonarQube による静的解析の CI 組み込み
- Obsidian による設計ドキュメント・ADR（意思決定記録）の運用

**実績・取り組み**

- **動画処理の性能設計**：`<video>` のシークが 25〜65ms を要し、毎フレーム描画では表示が破綻することを計測により特定。
  クリップを事前にフレーム列へ展開する方式へ切り替え、スクラブ操作を配列参照に変えることでフレームレートを安定化。
  また、シェーダーが 1 セルにつき 1 ピクセルしかサンプリングしない構造に合わせてフレームを低解像度で保持し、
  描画時に破棄される情報のためのメモリ消費を削減。
- **CI のセキュリティ設計**：GitHub Actions からのデプロイをキーレス化（Workload Identity Federation）し、
  長期認証情報を排除。加えて、OIDC プロバイダに `repository_id` / `repository_owner_id` による
  `attribute_condition` を設定し、GitHub 上の任意のリポジトリからトークンが発行できてしまう
  既知のなりすまし経路を遮断。関数ごとに実行サービスアカウントを分離し、必要な権限のみを付与する構成とした。
- **Secret を Terraform state に通さない設計**：シークレットの値は IaC の管理対象から外し、
  参照のみをコード化。Terraform state に機密値が残らない構成とした。
  併せて、state バケットにバージョニング・削除保護・公開アクセス防止を設定。
- **トレードオフの定量評価と記録**：問い合わせフォームの IP レートリミット層を一度実装した後、
  実効性（5 分 3 回の制限でも 1 日 864 通が通過、IP 分散に無効）と、
  その対価（プロジェクト全体への権限付与、障害時に fail closed でフォームが停止）を数値で比較し、**撤去を判断**。
  マネージドサービス（Cloud Armor）についても構成要件と課金構造から不採用とし、
  判断根拠・受け入れたリスク・再導入時の手順をコード内に記録した。
- **移植時のセキュリティ改善**：問い合わせ API を AWS Lambda + API Gateway + DynamoDB から Cloud Run へ移植する際、
  メール Subject への改行混入による SMTP ヘッダインジェクション、
  1 インスタンスが複数リクエストを同時処理する環境でのグローバル変数による CORS 応答の混線、
  リクエストログへの氏名・メールアドレス・本文の出力、SMTP タイムアウト未設定を、それぞれ設計レベルで修正。
- **公開範囲の設計**：稼働統計バッチにおいて、取得元 API のレスポンスに含まれる請求金額・顧客名・案件名を
  公開オブジェクトへ出力しない境界を定義し、コードとドキュメントの双方に明記。
- サプライチェーン対策として GitHub Actions を全て commit SHA でピン留めし、依存導入時のスクリプト実行を無効化。

**使用技術**

- 言語: TypeScript, Python, GLSL
- フレームワーク: Next.js 16 (App Router), React 19, Tailwind CSS v4, zod
- グラフィックス: WebGL2 / GLSL (GLSL ES 3.0)
- クラウド: GCP (Cloud Run Functions, Cloud Storage, Secret Manager, Cloud Scheduler, Artifact Registry)
- IaC: Terraform
- CI/CD: GitHub Actions, SonarQube
- セキュリティ: Workload Identity Federation (OIDC), Cloudflare Turnstile, 最小権限 IAM
- 開発環境: macOS

アジャイル開発

開発

- AWS サーバーレスアーキテクチャの設計・構築

  Tomcat Docker / Java 21 → API Gateway + Lambda (Java) → 同 (Python) と段を踏み、
  各段で並走期間を設けて現新比較しながら進めた

- クロスアカウント構成での S3 Batch Operations による大規模データ移行
- 旧環境・新環境の並走期間における現新比較のためのデータ同期基盤の構築・IaC 化
- アカウントをまたぐ IAM ロール・バケットポリシー・KMS キーポリシーの設計
- 走行データからの特徴量生成・抽出ロジックの設計・実装

品質・DevOps・運用

- コードレビュー
- CI パイプライン上での AI コードレビュー基盤の構築（MCP サーバー・AI Agent）
- 本番環境の監視設定・アラート設計
- 障害対応・インシデント対応
- リリース管理（PO レビュー、本番配信手順書の作成、本番マージの実施）
- IaC による環境構築と継続的な運用
- パフォーマンスチューニング

**実績・取り組み**

- 開発者が PO へ直接レビューを受けられる体制だったため、アーキテクチャの大幅な改善案を提案。
  採用されて実装まで担当し、システムを刷新のうえ本番リリースを完遂（**チームのリーダーではなく、提案が通ったメンバーという立場**）
- **最後の言語変更は計測で決めた。** Lambda の実装言語を Java から Python へ替えると
  実行メモリが半分以下になり、Lambda はメモリ×時間の課金なので規模が出るほど効く。
  起動時間も縮んだが、**そちらは SnapStart でも手当てできるので根拠にしていない**
- 常駐サーバーが無くなったので、常時稼働のインスタンス数はゼロになった。ただし
  **アーキテクチャ上のリソース数はむしろ増えている**（関数・キュー・テーブルに分かれるため）。
  「リソースが減った」とは言えない
- 週 2 回の PO-Dev ミーティングにおいて、技術提案・アーキテクチャ改善案をプレゼンテーション形式で提案し、
  システム全体の品質向上を継続的に推進
- CI パイプラインへの AI コードレビュー基盤（MCP サーバー・Amazon Bedrock Agent）を独自に設計・導入し、
  レビュー工数の削減とコード品質の底上げを実現
- 既存に AWS Glue による ETL 基盤を持つ大規模システムにおいて、重量級の分散処理を担う基盤として
  EMR Serverless 上の PySpark 環境を新規に構築・運用。既存の Glue 資産を作り直すことなく併存させ、
  処理特性に応じて両者を使い分ける構成とした
- 大規模な走行データから、モデル入力となる特徴量の生成・抽出ロジックを設計・実装。
  クラスタを常時稼働させないサーバーレス構成により、処理量に応じてリソースが確保される形とした
- システム移管に伴い、運転診断データを旧環境が置かれていた他社保有の AWS アカウントから、
  顧客企業自身が保有するアカウントへ移行。S3 Batch Operations による大量オブジェクトの一括コピーにあたり、
  コピー先のバケットポリシー、実行ロールの信頼ポリシー、暗号化に用いる KMS キーポリシーの三者を
  整合させたクロスアカウント権限設計を実施した
- 環境移行は一度の切り替えでは完了せず、旧環境と新環境を並走させて双方の出力を突き合わせる
  現新比較の期間を伴う。このためデータ移行を単発の作業ではなく反復実行可能な基盤として設計し、
  実行ロールと実行環境を IaC 化。検証を担当するメンバーが必要なタイミングで同一条件のデータを
  揃えられる状態を整備し、移行判断の前提となる比較作業を支えた
- 本番リリースについて、PO レビューによる承認、本番配信手順書の作成、本番ブランチへのマージ実行までを担当。
  開発だけでなく、本番環境の監視・障害対応・パフォーマンスチューニングを含む運用側も継続して担当した

**使用技術**

- 言語: Java, Python
- 分散処理・ETL: Amazon EMR Serverless（構築・運用）, AWS Glue（既存資産の併用）, Apache Spark (PySpark)

### エッジ AI 推論性能検証・PoC（2025 年 11 月 〜 2026 年 1 月）

**プロジェクト概要**
組込み向け AI アクセラレータの公称性能が、実ワークロードで有効かを検証する PoC。

**担当業務**
